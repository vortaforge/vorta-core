macroengine-datapack is archived but not abandoned. It was split into a core and 28 modules, each packaged as a Fabric mod that also works as a plain data pack. The archived entry stays because the original single pack still exists and still warns when loaded — see pack warnings. The replacement is documented at macroEngine.

Why they were archived

The reasons are recorded per project. The recurring ones are worth naming plainly, because they are the actual argument rather than a shrug:

  • Datapacks have no type safety. Every value crossing a function call, storage read, scoreboard comparison or macro expansion is an untyped string, checked by nothing at load time or run time.
  • They have no enforced security model. Dynamic command execution runs at function permission level with no authentication boundary a user can verify.
  • There is no debugging or inspection tooling beyond hand-written tellraw, and malformed references fail silently or at runtime rather than at build time.
  • The maintainer hit these problems as a plain datapack user, without installing any client mod.

What replaced them

Two Fabric mods, because the problems above are language problems that a datapack cannot solve from inside a datapack: afk-manager and join-throttle. Both are typed, tested and built by Gradle. See the mod guides.
