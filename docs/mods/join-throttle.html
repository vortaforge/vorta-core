join-throttle

Rate-limits connection attempts per source address, enforced before a full join completes.

What it actually does

The limiter is applied in PlayerManagerMixin, so it runs earlier than most join-side policies: an address that has exhausted its budget is refused before the player is fully admitted. Addresses are normalised by AddressKeys so that two spellings of the same address do not become two independent buckets — that would silently double an attacker's budget.

Settings

FieldDefaultRangeMeaning
maxJoins51 – 1000Allowed attempts per window.
windowSeconds301 – 3600Sliding window length.
exemptAddresses[]—Exact address keys to exempt.
denyMessage“Too many connection attempts…”—Disconnect screen text.
Exemptions are exact matches. Listing 10.0.0.1 does not exempt 10.0.0.10. If you exempt a whole range you are relying on prefix behaviour the mod does not implement, and it will look like the exemption silently failed.

Choosing values

The default (5 attempts per 30 seconds) suits a small server and is deliberately loose enough not to catch a player reconnecting after a crash. Tighten the window rather than the count if you are fighting a bot that is reconnecting in a loop: a low maxJoins with a long window punishes ordinary players who have flaky connections.

{
  "maxJoins": 5,
  "windowSeconds": 30,
  "exemptAddresses": [],
  "denyMessage": "Too many connection attempts. Please wait a moment and try again."
}
This is not a DDoS defence. It limits application-level join attempts per address. Traffic that never reaches the join handler, or that comes from many addresses, is outside what a mod at this layer can see.
