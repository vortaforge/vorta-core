1. What you clicked

You followed an open_url click event from inside a Minecraft chat message. Every VortaForge datapack that supports it prints a warning on load, and that warning contains a clickable link to this page. The message is not an error and nothing is broken — it is a deliberate, permanent notice.

The exact text depends on the pack, but the shape is always the same:

[PackName] archived & disarmed — not supported, not recommended.
            Click here to read why.

The clickable part is a text component in the modern click_event form, which Minecraft renamed from clickEvent in 1.21.5 (snapshot 25w02a). The open_url action takes url instead of the old value:

{"text":"Click here to read why.",
 "click_event":{"action":"open_url","url":"https://vortaforge.github.io/docs/docs/warnings.html"}}

Before 1.21.5 the same thing was written {"action":"open_url","value":"..."} inside a field called clickEvent. The two are not interchangeable: a pack built for format 71 (1.21.5) or newer must use click_event, and a pack built for an older format must not.

2. What "disarmed" means

Disarmed is a specific, checked property in this repository, not a feeling. Every archived project is registered in archived/archive.json with "disarmed": true, and a validator enforces it:

PropertyMeaning
statusarchived, frozen or superseded
disarmedThe pack must not be built, packaged or deployed by any workflow.
deploynot_recommended for every pack in this project.
original_pathWhere the pack used to live live; must not exist any more.

Concretely, this means:

  • No release contains these packs. The publishing job that used to build and upload pack ZIPs is disabled.
  • No Gradle task packages them. archived/ is deliberately not a scan root in settings.gradle, so an archived pack can never silently become a buildable subproject again.
  • The website does not list them as downloads.
  • The repository guard refuses new datapack content and refuses to revive archived tooling.

3. How the gate works

"Gate" in this project means one of two things, and both are real mechanisms rather than a label in a README.

The in-pack load gate

A gated pack does not run until a player consents. The pattern, as implemented in the largest pack, is a single authoritative score that anything else may query:

# macroengine:gate/is_open
# Answers whether the pack is usable, without printing anything.
# Deliberately has NO gate guard: its whole job is to answer while the pack is closed.
execute if score #macroengine.open vortaforge.gate matches 1 run return 1
return 0

Callers check it before relying on the pack: execute if function macroengine:gate/is_open run function mypack:use_it. The gate has a consent prompt, a decline path, a permit list and a way to revoke, so "closed" is the default and opening it is an explicit act.

Packs that never had a gate now carry the archived warning described above. A warning is not a security boundary: it tells the truth about the pack's status, it does not make an ungated pack safe. Do not read a warning as an audit.

The repository guard

Separately, scripts/repo/datapack_guard.py is a fail-closed check that runs in pre-commit, pre-push, CI and Gradle. It refuses new datapack content, revived archived tooling, blocklisted accounts, a tripped kill switch and an inconsistent archive registry. That guard protects the repository; it cannot protect a world that already has a pack installed.

4. Why some packs cannot show the warning

click_event arrived in Minecraft 1.21.5, data pack format 71. A pack targeting an older format physically cannot render a clickable link in the new syntax, and writing the new syntax into an old pack would break it. So the warning has two renderings:

TargetFormatWarning rendering
1.21.5 and newer≥ 71click_event link to this page
1.21.4 and older< 71plain chat warning plus an unpaginated URL
1.20.5 and older≤ 41plain warning; functions/ directory layout

The plain rendering says the same thing. It only lacks the click target. This is honest about a real constraint instead of shipping a command that would error on the version the pack was written for.

5. If you still want to run a pack

You can. Nothing here is remotely disabled, and a datapack is just files. But understand what you are accepting:

  • No support. Issues will be closed as out of scope.
  • No fixes. Bugs in archived packs are not going to be fixed.
  • Old formats are genuinely old. Some of these packs target Minecraft 1.16.2–1.19.4. Modern versions changed directory layouts (functions/ became function/ in 1.21), text components, and command syntax. A pack that loads may still do nothing.
  • Back up the world first. Datapacks run commands with the server's permissions. That is not a VortaForge-specific risk; it is what datapacks are.

The one thing worth taking away

A chat warning tells you a pack's maintenance status. It does not tell you the pack is safe to run, and it does not gate anything. The gate is the consent flow; the warning is the label on the box.
