macroEngine

One engine, split into a core and twenty-eight modules you install a la carte. Every module is a Fabric mod that also works as a plain data pack.

Status. This is the rebuilt macroEngine, not the archived macroengine-datapack. The original single pack is still archived and still warns when you load it; see the pack warnings. This page describes the split that replaced it.

What it is

macroEngine is a command-driven engine for Minecraft data packs: a scheduler, a permission layer, player and world state, an event bus, hooks, and a large function API on top. The original shipped as one data pack of roughly 1,300 functions. That pack is now split into one core and 28 modules, each packaged as a Fabric mod.

The split exists so that installing the engine does not mean installing all of it. A server that never touches permissions does not load the permission module, and its functions are not in memory.

The one rule the layout rests on

Every module depends on the core. No module depends on another module. Where one feature needs another, the call goes through a hook slot the core owns — the core defines the slot, and whichever module implements the concept fills it.

This is not tidiness. It is what makes a module removable: with the rule held, you can delete any one jar and the remainder still loads. That property is checked automatically — see architecture.

Install

  1. Fabric loader for Minecraft 26.3, Java 25.
  2. Fabric API is required. The pack inside each jar is read by fabric-resource-loader, which ships in Fabric API, not in the loader. Every manifest declares the dependency, so a missing Fabric API stops the game with a readable message rather than loading 29 mods that do nothing.
  3. Drop me_core_module in mods/, plus whichever modules you want.

Or use it as a data pack

The same jar works in a world’s datapacks/ folder with no mod loader at all. The jar root holds pack.mcmeta and data/ at exactly the paths the game expects; the Fabric metadata is additional, not a wrapper. That is the compatibility promise the original pack had, kept.

What is inside a jar

me_cb_module-1.0.0.jar
├── fabric.mod.json                       id `macroengine-cb`
├── com/vortaforge/macroengine/
│   └── macroengine_cb/MacroEngineEntry.class   the ModInitializer
├── pack.mcmeta                           data pack manifest, format 121
└── data/me_cb_module/...                 the pack itself

The class exists because Fabric requires one. It implements ModInitializer and does nothing: the behaviour is the data pack, which Fabric reads out of the jar’s data/ directory. Nothing is registered from Java.

A class that is merely present is not enough. Fabric constructs the declared entry point and casts it to ModInitializer. A class that does not implement the interface fails that cast and stops the entire server, not just the offending mod. This project shipped that once.
